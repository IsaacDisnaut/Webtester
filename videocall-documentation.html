1. What This Application Does

This is a browser-based video communication platform with two modes of use:

  • Person-to-Person Video Call — two people join the same room code and talk face-to-face using their cameras and microphones.
  • Robot Control Mode — one person controls an InMoov humanoid robot head in real time. A 3D model of the robot head is displayed and animated. Commands (head rotation, jaw, eye movement) are sent to a physical robot over MQTT.

Additional features include real-time text chat, AI assistant integration (Anthropic Claude or OpenAI), and automatic speech-to-text / text-to-speech so conversations can be read aloud or transcribed.

The server acts only as a signaling relay — it never touches the actual audio or video stream. Once two peers exchange connection details (ICE candidates + SDP offer/answer), their video streams flow directly between browsers over WebRTC.

4. Server — server.js

The server has four responsibilities:

4.1 Static File Serving

express.static('public') serves all HTML, CSS, JS, URDF, and STL files directly to the browser. No templating engine is needed.

4.2 REST API Endpoints

EndpointMethodWhat it does
/api/aiPOSTProxies a chat request to Anthropic Claude or OpenAI. The browser sends its API key; the server forwards it and returns the AI reply. This avoids CORS issues from calling AI APIs directly in the browser.
/api/ice-configGETReturns a list of STUN/TURN servers for WebRTC ICE negotiation (Google STUN + OpenRelay TURN).
/api/session/startPOSTRecords a new user session in SQLite with the user's name and login time.
/api/session/endPOSTUpdates the session record with usage time and logout time.
/api/session/end-beaconPOSTSame as above but designed to be called by navigator.sendBeacon() when the browser tab is closed.
/api/sessionsGETReturns the last 200 session records (for admin review).

4.3 Socket.io Signaling

WebRTC requires an out-of-band signaling channel to exchange connection setup messages. Socket.io provides this real-time relay:

  • join-room — A peer announces they want to join a specific room code.
  • room-joined — Server replies with the list of existing peers in that room.
  • peer-joined / peer-left — Broadcast to the room when someone arrives or leaves.
  • signal — Relay WebRTC SDP offers/answers and ICE candidates between peers.
  • chat-message — Relay text chat messages within the room.
  • peer-tts — Relay whether the peer has auto-read (TTS) enabled.

4.4 Development vs Production Mode

In development (NODE_ENV not set), the server generates a self-signed HTTPS certificate and runs on port 3443. HTTPS is required for getUserMedia() (camera/microphone access) in browsers.

In production (Railway), NODE_ENV=production is set automatically. The server runs plain HTTP on port 3000 because Railway's edge proxy handles HTTPS termination.

5. Frontend — app.js

5.1 Login & Room System

1
User enters their name and a room code. Any two people who type the same room code will be connected to each other.
2
The browser emits join-room over Socket.io. The server records the session start in SQLite.
3
If another peer is already in the room, room-joined returns their socket ID and the WebRTC handshake begins automatically.

5.2 WebRTC Connection Flow

1
Offer — The first peer creates a WebRTC RTCPeerConnection, adds camera/mic tracks, generates an SDP offer, and sends it via Socket.io signal.
2
Answer — The second peer receives the offer, creates its own connection, and sends back an SDP answer.
3
ICE Candidates — Both sides send network path candidates to each other. The browser tries each candidate (local network, STUN-discovered public IP, TURN relay) until a working path is found.
4
Stream flows — Once ICE negotiation succeeds, audio/video travels directly peer-to-peer. The server is no longer involved in the media stream.

5.3 Speech — STT & TTS

  • Speech-to-Text (STT) — Uses the browser's built-in SpeechRecognition API (Web Speech API). When active, the user's spoken words appear in the chat input box in real time.
  • Text-to-Speech (TTS) — Uses speechSynthesis.speak(). When "Auto-Read" is enabled, incoming chat messages from the peer are read aloud automatically.
Mobile limitation: The Web Speech API requires HTTPS and a stable internet connection. On some mobile browsers (especially Android), SpeechRecognition may not work due to network restrictions. The app shows a "Speech network error" warning if this happens.

5.4 AI Chat Integration

The settings panel allows entering an API key for either Anthropic Claude or OpenAI. When a message is sent in AI mode:

  • The full conversation history is sent to POST /api/ai on the server.
  • The server forwards it to the chosen AI provider and returns the reply.
  • The reply appears in the chat as an "AI" message bubble.
  • A custom system prompt can be configured to change the AI's persona.

6. Robot Control Panel

6.1 Overview

The Robot Control tab shows a 3D animated model of an InMoov humanoid robot head. Controls let the operator move the head, open/close the mouth, and move the eyes. These movements are mirrored on the 3D model and sent as MQTT commands to a physical robot.

6.3 How the 3D Viewer Works (robot-viewer.js)

1
URDF Parse — The browser fetches /robot/head.urdf and parses it with DOMParser (no ROS required). It extracts all <link> and <joint> elements.
2
STL Load — For each <visual> element found inside each link, THREE.STLLoader loads the matching STL file from /robot/meshes/. Each mesh is added to a Three.js Group representing that link.
3
Joint Hierarchy — Each joint creates two nested Groups: an origin group (fixed position offset from parent) and a pivot group (rotates to simulate joint movement). The child link's meshes sit inside the pivot group.
4
Coordinate System — URDF uses Z-up coordinates (Blender convention). Three.js uses Y-up. The root group is rotated −90° around X to convert between them.
5
Scale — Mesh vertices are in Blender units (~8.33× centimetres). A scale factor of 0.1196 (from the InMoov model's properties.xacro) is applied to the root group so the head measures approximately 1.80 m tall at full-body scale.
6
Animation — When setJoint(name, angle) is called, the pivot group's quaternion is updated with setFromAxisAngle(axis, clampedAngle). A requestAnimationFrame loop re-renders the scene at 60 fps.

6.4 MQTT Publishing

Every time the robot state changes, the browser publishes a JSON message directly to the MQTT broker using the MQTT.js library (loaded from CDN). The format is:

{
  "Pad":    "left" | "right" | "up" | "down" | null,
  "Analog": { "x": -1.0…1.0, "y": -1.0…1.0 }
}

The MQTT broker address and topic are configurable in the app's settings panel. The physical robot's control software subscribes to the same topic and actuates the servos accordingly.

6.5 InMoov Model File Origin

The STL mesh files and URDF joint definitions come from the open-source inmoov_urdf-master project (CC BY-NC 4.0 licence, original creator: Gaël Langevin / inmoov.fr). Only the head assembly is included. The URDF was extracted from inmoov_urdf-master/archive/urdf/InMoov.urdf and stripped down to the head joints only.

7. Deployment on Railway

7.1 How It Works

The application is deployed as a Docker container on Railway. Railway automatically detects the Dockerfile, builds the image, and runs it on every push to the main branch of the GitHub repository.

7.2 Dockerfile Explained

FROM node:20-slim
# Install C++ build tools required by better-sqlite3 (native addon)
RUN apt-get update && apt-get install -y python3 make g++

WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev      # install production dependencies only

COPY . .                   # copy all source files
ENV NODE_ENV=production    # enables production mode in server.js
EXPOSE 3000
CMD ["node", "server.js"]

10. Glossary

TermMeaning
WebRTCWeb Real-Time Communication — a browser standard for direct peer-to-peer audio/video without plugins.
ICEInteractive Connectivity Establishment — the process of finding a working network path between two peers.
STUNSession Traversal Utilities for NAT — a server that tells a browser its public IP address so peers can find each other.
TURNTraversal Using Relays around NAT — a fallback relay server used when direct peer-to-peer is blocked by a firewall.
SDPSession Description Protocol — a text format describing the media capabilities (codecs, resolution) of each WebRTC peer.
Socket.ioA WebSocket-based library that enables real-time bidirectional events between browser and server.
MQTTMessage Queuing Telemetry Transport — a lightweight publish/subscribe messaging protocol widely used in IoT and robotics.
URDFUnified Robot Description Format — an XML file format that describes a robot's physical structure (links and joints).
STLStereolithography — a 3D mesh file format describing geometry as a list of triangles. Used for robot mesh files.
Three.jsA JavaScript library that makes WebGL 3D graphics accessible in the browser without writing raw GPU shader code.
InMoovAn open-source 3D-printable humanoid robot designed by Gaël Langevin (inmoov.fr).
RailwayA cloud hosting platform that deploys Docker containers automatically from a GitHub repository.
SQLiteA lightweight, file-based relational database. Used here to log user session records without needing a separate database server.
